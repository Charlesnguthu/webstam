# Blog publishing and deployment

Articles are managed in Django Admin. Authors are Django users; add a category, write the article body in the supported Markdown subset (headings, paragraphs, lists, links, inline emphasis/code, and fenced code blocks; raw HTML is escaped), provide a meaningful image alt text, and save as Draft. Preview is available from the article admin change screen at its `Preview` URL; it requires staff status and model view or change permission and returns `X-Robots-Tag: noindex, nofollow`.

For immediate release, choose Published and set a publication time that has arrived. For a future release, choose Scheduled and set a future time. Public queries include due scheduled articles by comparing their timezone-aware `published_at` against Django's configured timezone. This means a scheduled article becomes visible on the first request/feed/sitemap query at or after that time without a background process. It does not run a job at an exact instant. Configure a scheduler only if exact-time side effects (such as notifications) are later required.

Set `PUBLIC_DOMAIN` to the verified production hostname before deployment. Production sitemap requests are already disabled when this value is absent. Configure persistent `MEDIA_ROOT` or a durable object storage backend: article images are user-uploaded media and must survive application restarts and deployments. Production `DEBUG` should remain false and must use a persistent database. No fabricated articles are included; the blog starts with a useful empty state. RSS is available at `/blog/feed.xml`.
